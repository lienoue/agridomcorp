    🔑 Logique Mode Junior

    Règle : Tout utilisateur de moins de 18 ans voit automatiquement mode_junior=True activé.

    Signal post_save

    Le signal suivant s'assure que tous les mineurs ont mode_junior=True, quel que soit le chemin de création (formulaire, admin, script) :

    @receiver(post_save, sender=User) def activer_mode_junior_pour_mineurs(sender, instance, created, **kwargs): if not instance.birth_date: return today = date.today() age = today.year - instance.birth_date.year - ( (today.month, today.day) < (instance.birth_date.month, instance.birth_date.day) ) if age < 18: if not instance.mode_junior: User.objects.filter(pk=instance.pk).update(mode_junior=True) instance.mode_junior = True

    ⚠️ Ce signal NE crée PAS d'Eleve

    Un mineur n'est pas forcément un élève. Le profil Eleve est créé uniquement quand :

    • L'utilisateur passe par inscription_eleve (avec code de classe)
    • Ou un enseignant crée le compte manuellement

    🔒 Blocage Premium pour mineurs

    Un mineur sans classe n'a pas accès aux fonctionnalités Premium, sauf s'il passe par une autorisation parentale.

    Vérification d'accès

    def verifier_acces_abonnement(user, plan_requis=None): if plan_requis is None: return True, None try: abonnement = user.abonnement if abonnement.est_actif and abonnement.plan.nom in ['PREMIUM', 'ENSEIGNANT']: return True, None if abonnement.est_actif and abonnement.plan.nom == plan_requis: return True, None return False, f"Cette fonctionnalité est disponible avec {plan_requis}." except Abonnement.DoesNotExist: return False, f"Cette fonctionnalité est disponible avec {plan_requis}."

    💳 Autorisation parentale

    Modèle AutorisationAchatMineur pour valider les achats des mineurs.

    Workflow complet

    1. Mineur clique sur "S'abonner"
    2. Blocage dans create_checkout_session (pas d'autorisation valide)
    3. Redirection vers demander_autorisation_achat
    4. Formulaire parent (nom, prénom, email)
    5. Email envoyé au parent avec token unique
    6. Parent clique sur le lien (valider_autorisation_achat)
    7. Parent valide OU refuse
    8. Si validé → mineur peut payer via Stripe
    9. Autorisation valable 7 jours

    Champs du modèle

    ChampTypeDescription
    utilisateurForeignKeyLe mineur
    plan_souhaiteForeignKeyPlan visé
    parent_nom / parent_prenomCharFieldNom du parent
    parent_emailEmailFieldEmail de validation
    statutChoiceen_attente / validee / refusee / expiree
    token_validationCharFieldToken URL unique
    date_expirationDateTime+7 jours
    ip_validationGenericIPPreuve légale
